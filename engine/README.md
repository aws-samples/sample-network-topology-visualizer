# Python collection engine

The Python engine collects AWS network configuration through read-only APIs and produces topology JSON conforming to `schema/topology.schema.json`. It produces observations as separate JSON conforming to `schema/observation.schema.json`. The renderer visualizes the topology and observations generated by the engine.

## Installation and execution

Python 3.12 or later is required. Specify the collection region and a read-only AWS profile.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e './engine[dev]'
.venv/bin/nettopo collect --profile PROFILE --region REGION \
  --accounts ACCOUNT_ID --out out/snapshot.json

.venv/bin/nettopo observe --profile PROFILE --topology out/snapshot.json \
  --out out/observation.json
```

For `collect`, use `--out` to specify the topology JSON path. For `observe`, pass that topology JSON path through `--topology` and specify the observation JSON path through `--out`.

See `nettopo collect --help` and `nettopo observe --help` for additional options.

## Output data

- Store network configuration in topology JSON and observations (current resource state and traffic results) in separate observation JSON.
- The renderer compares the topology's content digest with the topology digest recorded in observation JSON to check that the observations match the current topology. If either digest is absent, compare topology collection times.
- Record collection status and failure reasons in output JSON `coverage`. The required `item_count` field is `null` when the listing count is unknown and `0` for a successful empty listing.
- Omit relationships to unresolved resources and record why they could not be resolved in output JSON.
- Resource and relationship `partial` (incomplete information) and relationship `directed` (directionality) are required output fields. Emit fields and resource lists in a consistent order.
- Topology JSON includes account IDs, CIDRs, and IP addresses.

## Tests

Tests reproduce successful and failed queries using mock AWS API responses. Set AWS credentials to test-only `dummy` values.

```bash
.venv/bin/python -m pytest engine -q
```
